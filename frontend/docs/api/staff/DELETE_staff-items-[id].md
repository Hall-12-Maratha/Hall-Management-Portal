# DELETE /api/staff/items/{item_id}

**Group:** staff
**Implementation:** `frontend/src/app/api/staff/items/[id]/route.ts`
**FastAPI origin:** `backend/app/routers/staff.py::delete_item`

Without `permanent`: deactivate the item (soft delete) so booking history is
preserved. Restart it with `PUT ... { "is_active": true }`.

With `?permanent=true`: remove the row for good. Refused while the item has
any booking.

Either form ends the weekly series the item belongs to, from that item on.
Whether the item is the weekly rule itself or one of its generated
occurrences (matched by name, meal and weekday to a rule dated before it):

- the rule is deactivated (deleted instead when `permanent` and it has no
  bookings) so the recurring-items job stops generating weeks;
- later occurrences without bookings are hard-deleted;
- later occurrences with bookings are set inactive (history kept);
- earlier weeks are left alone.

This matters because the recurring-items job (`lib/server/jobs/recurringItems.ts`)
runs lazily every 15 minutes from the item list endpoints and recreates any
missing week of an active rule. Deactivating or deleting a single occurrence
without stopping its rule would make the row come back on the next run.

## Auth

- Header: `Authorization: Bearer <access_token>`
- Roles: mess_staff

## Request

- Path params: `item_id` (integer)
- Query params: `permanent` (`true` / `1`, optional)

## Response

`200`:

```json
{ "message": "Item deactivated. Also its weekly item stopped, 1 upcoming week removed." }
```

The message starts with `Weekly item stopped.` / `Item deactivated.` /
`Weekly item deleted permanently.` / `Item deleted permanently.` and, when the
series was affected, appends what else happened (rule stopped, N upcoming
weeks removed, N booked weeks hidden). The staff page shows it as the toast.

## Errors

| Status | `detail` | When |
|---|---|---|
| 404 | `Item not found.` | unknown id |
| 409 | `This item has N bookings and cannot be deleted. Stop it instead, or clear its bookings first.` | `permanent=true` on an item with bookings |
| 422 | `item_id: must be an integer.` | bad path param |
| 401 / 403 | guard messages | missing token, inactive, wrong role |

## Side effects

- Sets `is_active = false` on the item (or deletes it with `permanent`).
- Stops the weekly series from this item on: rule deactivated (or deleted),
  later unbooked occurrences deleted, later booked occurrences deactivated.
- Existing bookings are untouched.

## Business rules

- Inactive items disappear from `GET /api/items` and cannot be booked.

## Changes vs FastAPI

- Adds permanent deletion (guarded by the bookings check) and weekly-rule propagation.
- Deleting a generated occurrence stops its parent rule too (2026-11-13), so a
  deleted week cannot be regenerated by the recurring-items job.
